按 `网站制作需求1027.docx` 从零开发，目录 = 工作区根目录（`xingyi-booking`）。

**技术选型**
- Next.js 15.5 App Router + React 19 + TypeScript + Tailwind CSS v4
- Drizzle ORM + 双驱动：未配 `DATABASE_URL` 用 PGlite（嵌入式 Postgres，数据 `./.data/pg`），配了走 node-postgres

**关键实现点**
- 防超卖：单条条件 UPDATE `seats_confirmed + seats_held + qty <= capacity`，不用 SELECT 判断（已并发验证）
- 支付：模拟网关 + 带 HMAC 签名的服务端 webhook，只认通知不认跳转；`eventId` 唯一保证幂等
- 安全链接：明文 token 给 URL，库里存 sha256 校验 + AES-256-GCM 密文（供原样重发邮件）
- 邮件：统一入口 `src/lib/email.ts` 的 `sendEmail()`，无 Key 降级为后台邮件日志
- 客户端组件不能引 `src/lib/config` 链到 db → 拆出 `src/lib/settings.ts`（db 相关）与 `src/lib/config.ts`（纯常量）

**环境坑**
- PGlite 的 nodefs 不会递归建目录，需先 `mkdirSync('./.data')`
- `next dev` 启动时清理 `.next` 会触发本环境的批量删除保护（count>50）导致崩溃 → 用 `mv .next .next.bak.*` 规避，别 `rm -rf`
- 工作区上级有 `C:\Users\zyd\package-lock.json`，需在 next.config 设 `outputFileTracingRoot`
- npm install 首次约 20 分钟

- 原 `src/db/index.ts` 对非 localhost 地址强制 `ssl:{rejectUnauthorized:false}` → 自建库未开 SSL，报
  `The server does not support SSL connections`（node-postgres 默认 sslmode=prefer 会先发 SSLRequest 且不回退）
- 修复：新增 `sslOptionsFromUrl()`，按 URL 的 `sslmode` 决定；**默认关闭**，需要时加 `?sslmode=require`
- 同理 `scripts/reset.ts` 也按此判断

- ⚠️ `check-db.ts` / `reset.ts` 无静态 import 会被当成全局脚本 → TS2393 重复 main，需加 `export {}`
- ⚠️ `npm run db:*` 不带 `--env-file`，操作远程库必须 `npx tsx --env-file=.env.local scripts/xxx.ts`
